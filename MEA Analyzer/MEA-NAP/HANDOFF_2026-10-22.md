## 1. The experiment, in one paragraph

Cortical cultures on 60-electrode MCS arrays (200 µm pitch, labels "cr" =
column/row 1–8, corners missing). A Polygon DMD projects a laser pattern that
repeats once per cycle; an MCS digital trigger fires once per Polygon frame.
Two patterns: a thin bar sweeping bottom-right → top-left (`Sept2021_SweepBRtoTL.seq`,
160 frames/cycle, nominal axis 135°), and a thin ring expanding from the array
centre (`Oct2026_RadialCenterOut.seq`, 133 frames/cycle, centre between
electrodes 44/45/54/55). Each recording is ~60 min: 2.5 min pre, 55 min stim,
2.5 min post (Batch.csv windows). The question is whether the network locks to
the stimulus geometry during stim and retains it afterwards, across training
days D1…D5 and replicate samples. Batch.csv groups: `sweep1..3`, `radial1..3`
(plus controls / speed groups like `4000um`).

## 2. Phase lock-in module — what it computes

File: `MEA-NAP\mea_nap_phase_lockin.py`. The docstring at the top is current.

### 2.1 Per-electrode phase (unchanged all session, `electrode_locking`)
For electrode e with spike times t_k inside a window and period T:
`φ_k = 2π·frac(t_k / T)`, `z_e = (1/n) Σ e^{iφ_k}`.
`|z_e|` = vector strength (PLV / Rayleigh R̄), `arg z_e` = preferred phase.
Gate: n ≥ `min_spikes` (15). Electrodes below it are dropped, not zeroed.
The resultant is the Fourier component of the spike train at the stimulus
frequency; it only captures the fundamental (a bimodal phase distribution
cancels — a second-harmonic readout was discussed, not built).

### 2.2 Period
Seed = frames / trigger_hz (`_period_seed_for_stem`; trigger rate from
`mea_nap_digital_events.sweep_metrics`). Since 2026-10-22 `frames` comes from
the optional 7th Batch.csv column per recording, else `PHASE_LOCKIN.frames_per_sweep`.
Guard `max_trigger_period_s` (120 s) rejects implausible trigger periods
(flood controls) → autocorrelation seed. `refine_period` searches ±30 % of the
seed (objective "pooled" = total locking strength). Stim is fitted first and its
refined period seeds pre/post (`carry_T`). `min_cycles` (2) rejects windows
shorter than two cycles.

### 2.3 Linear (sweep) spatial model — `fit_plane_wave`
Matched filter `P(k) = |Σ_e w_e z_e e^{-i k·x_e}| / Σ w_e`, `w_e = √n_e`,
over a 121×121 grid of k in ±π/pitch, then parabolic refinement. Direction =
atan2(k), speed = 2π/(|k|T), coherence = P(k*). Since 2026-10-19 the grid is
evaluated as ONE matrix product (`e^{-i(kx x+ky y)}` factorises) — identical to
the old double loop to 1e-13°, ~900× faster. `permutation_pvalue` already used
this construction. Flags: `low_confidence` (peak_ratio < 1.8 or coherence <
0.10), `no_propagation` (phase span across the array < `min_phase_span_rad`
0.6 → k≈0, flood-like).

### 2.4 Radial spatial model — `quadrant_alignment`  (built 2026-10-18)
A ring is not a plane wave; the whole-array planar fit on radial data returns
a confident-looking, meaningless heading (verified on synthetic data: 105° at
coherence 0.13, above the floor). Chosen approach (the user's): split the
array into four quadrants about `_RADIAL_CENTRE_CELLS = (4.5, 4.5)`, run the
same `fit_plane_wave` in each, and score each quadrant's heading against its
OWN expected outward direction = bearing from the centre to that quadrant's
locked-electrode centroid (centroid, not fixed 45°/135°…, because a planar fit
over a ring patch points at the patch centroid and grounding moves it).
Outputs: per-quadrant heading/deviation/coherence/speed/flat flag,
`mean_deviation_deg` (circular mean), `deviation_consistency` (|R| of the
deviations), `radial_alignment` (mean cos), `mean_convergence_pct`. Needs ≥2
fitted quadrants (`_RADIAL_MIN_QUADRANTS`); a quadrant with <6 locked
electrodes is drawn "no fit". Radial groups are recognised by group name
prefix `radial` (`_is_radial_group`). The sweep axis parameter is not used
anywhere in radial outputs (verified by tracing every use).

A true radial matched filter `P(c, k_r) = |Σ w z e^{-i k_r |x-c|}|` was
prototyped (`dev\radial_proto.py` — not installed): recovers the centre to
0.1 pitch on synthetic data, but it NESTS the planar model (centre → ∞), so
raw coherence cannot pick between them; the discriminator is whether the best
centre lies inside the array. Speed came out ~9 % high in one realisation —
unverified across seeds. Kept as a future option.

### 2.5 Convergence over time — `_direction_timecourse`, `_draw_direction_axes`
Each region is cut into `direction_window_s` (60 s) bins; the locks are
recomputed per bin with the region's refined period and the spatial model is
re-fitted (planar, or quadrant for radial). Score per bin: **% convergence =
50·(1 + cos(deviation))**, i.e. the summary's `alignment` rescaled to 0–100 %
(135° → 100 %, −45° → 0 %). Linear: deviation from the sweep axis. Radial:
mean over quadrants of each quadrant's convergence on outward (averaging
convergences, not signed angles, so opposite errors cannot cancel to 100 %).
Bins are placed on the recording's absolute clock from each unit's `win`, so
pre/stim/post bands sit where they really are. Plot: ±1 SEM bars at bins that
have one (mean plot: across samples; radial: across quadrants; a single-sample
sweep bin has none), a Gaussian-smoothed line across the whole session
(`direction_smooth_bins`, default 1.0, PLOT-ONLY), coloured by per-row
normalised coherence. Bands use the "Blues" ramp (pre light → stim dark →
post mid) with text labels.

`_fig_direction_means`: averages replicate samples per training day
(day from `_D<n>` in the stem; replicates = groups differing only by a
trailing number, e.g. sweep1/2/3 → condition "sweep", or several files in one
group). Bins aligned by (epoch, bin index), not clock time.

### 2.6 Figures (all under `<PLOT_DIR>\Phase Lock\`)
`phase_lockin_<group>.png` (electrode map, colour = lock strength normalised
PER PANEL, one 0–1 colourbar per row; heading arrow + crimson sweep axis, or
quadrant arrows + outward lines for radial), `phase_flow_<group>.png`
(streamlines of `∇arg Z = Im(Z̄∇Z)/|Z|²` on a Gaussian-interpolated complex
field — wrap-safe), `phase_compass_<group>.png` (polar: preferred phase vs
strength, rose, mean resultant), `phase_direction_<group>.png`,
`phase_direction_mean_<condition>.png`. Grid: rows = samples sorted youngest
age first, left "Blues" day strip, columns pre / stim / post. **Since
2026-10-21 the POST column of the first three is fitted over only the first
`post_map_window_s` (150 s) of post** (stored as `results["post_early"]`,
column title "post (first 150 s)"), to be comparable with the 150 s pre;
the convergence curves use the full post. All `max |z|` corner tags were
removed at the user's request; absolute values live in the CSV.

### 2.7 Summary CSV
`phase_lockin_summary.csv`: one row per sample × region (pre, stim, post,
post_150s). Columns: direction_deg, speed_um_per_s, coherence, period_s,
peak_ratio, alignment, n_locked, phase_span_rad, propagation, p_value,
low_confidence, frames_per_sweep; radial rows add pattern, n_quadrants,
mean_deviation_deg, deviation_consistency, q{TL,TR,BL,BR}_{heading,deviation,
coherence} and blank the planar-only columns. `pattern` appears only when a
batch mixes radial and linear groups.

### 2.8 Results cache + Replot (2026-10-20)
`run_phase_lockin` = compute (`_analyse_stem` per sample) → `_save_results`
(`phase_lockin_results.pkl` v1 + `.json` manifest: params, stems, groups) →
`_render_results`. `replot_phase_lockin()` re-renders from the cache with the
CACHED params except `_PLOT_ONLY_KEYS` (taken live), logs any other param that
differs, and warns if the cache predates the early-post fit. GUI: "↻ Replot"
button (bottom bar) → `App._replot_worker`. Verified: delete all outputs →
replot → 11/11 byte-identical.

### 2.9 Parallel sampling (2026-10-19)
`_analyse_stem(stem, units, p, seed_T)` is pure (no GUI, no `io.CONFIG`).
`_analyse_parallel` runs it in a `spawn` `ProcessPoolExecutor`
(`n_workers`: 0 = cores−1, 1 = serial, ≤16, ≤n_samples); trigger files are
read in the parent; results are assembled in Batch.csv order; abort cancels
futures; any pool-level failure logs and falls back to serial for the
remaining samples; `_worker_entry` nulls stdout/stderr for pythonw. Serial vs
2-worker verified deep-equal bit for bit. Real-machine speed-up never measured
(sandbox had 2 cores) — ask the user what the log line
"analysing N sample(s) on K worker process(es)" reports and the wall time.

### 2.10 Cost model after vectorisation
~9 s per 60-min sample (regions + 200-permutation p-value ≈ 9 s, time course
≈ 0.2 s). Remaining exact speed-ups, not done: slice spikes once per window
so `refine_period`'s 306 `electrode_locking` calls stop re-slicing (~3.5 → 1 s);
process pool already covers the rest.

### 8.2 Phase lock-in: what CAN mislead (found on the real summary CSV)
1. **p-value.** The phase-rotation null rejects whenever electrode phases are not
   independent, which synchronous bursting alone guarantees (a flat k~0 map). On
   the Oct batch: 67/70 linear rows at the floor, including every pre, post and
   all 10 no-stimulus controls. Recomputed from the cache with a POSITION-shuffle
   null (positions permuted, each electrode keeps its z; k=0 invariant):
   stim 15/15 significant, pre 1/15, post 2/15, controls 0/10. New parameter
   `PHASE_LOCKIN.null_model` = "rotation" (default, unchanged) | "position"
   (GUI entry + tooltip added). Switch to "position" for a propagation test.
2. **That run had the guards off**: `min_phase_span_rad 0`, `min_cycles 0`,
   `min_spikes 5`, `refine_objective spatial`. Hence `propagation = True` on every
   row and speeds up to 1.6 m/s in pre windows (k~0, span 0.002 rad). The
   "spatial" objective also selects the period on the statistic the p-value
   tests. Defaults (0.6 rad, 2 cycles, 15 spikes, pooled) restore the flags.
3. `_direction_timecourse` applies NO span / coherence gate to its bins, so
   pre/post convergence curves are drawn from k~0 fits with random headings
   (they smooth towards 50 %). Gating bins by `min_phase_span_rad` would change
   the plots -- not done, offered.
4. The period refinement grid (1 % coarse, 0.15 % fine) is far wider than the
   tuning width of a 55-min window (~0.06 %), so for stim it always returns the
   trigger-derived seed (CSV: 3.200 s / 2.660 s on every stim row). Harmless
   while the seed is exact; a seed error > 0.1 % would silently weaken locking.
   Folding on the actual trigger timestamps would remove the dependence.
5. Fitted "speed" rises day 1 -> 5 (1.5 -> 2-4 mm/s) as `phase_span_rad` falls:
   with synchrony k -> 0 and 2π/(|k|T) inflates. Read speed with the span column.
6. Minor: compass "0 deg = cycle start" is relative to the window start, not the
   stimulus frame; a radial row with 0 fitted quadrants keeps the planar
   `alignment` value.
